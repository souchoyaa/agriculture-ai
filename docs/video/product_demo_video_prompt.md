# Product Demo Video Prompt

Create a polished hackathon product demo video for this project.

## First: understand the current project

Inspect the current repository before deciding what the video is about. Read the README, challenge brief, relevant documentation, recent changes, and current implementation. Run the product if possible. Compare the current product with earlier plans or descriptions you find in the repository.

The project may have changed or gained functionality. Identify what is newly implemented, what is distinctive, and what works end to end now. Treat the current implementation as the source of truth. Do not omit a valuable new feature just because it was absent from an earlier plan.

Choose the story, audience, problem, product flow, and features yourself based on what you find. Select at most three features to show, prioritizing the ones that make the clearest and most compelling demo. Do not try to cram every feature into the video.

Do not ask me to choose the narrative. Make a reasoned choice from the project, briefly explain it, and continue to production.

## Video brief

- Target length: approximately 50 seconds.
- Absolute maximum: 60 seconds, including the closing shot and any fade-out.
- Format: 16:9 landscape, 1920×1080, 30 fps, suitable for a hackathon projector.
- Use the attached reference video for punchy pacing and visual energy, not for its content.
- Make it feel like a memorable product-launch teaser combined with a real hackathon demo: cinematic, confident, modern, and easy to understand.
- Keep the real product interface central. Do not substitute generic AI imagery for the actual product.

## Suggested rhythm

Treat these as pacing guidance, not a fixed script. Adapt the sequence to the strongest story supported by the project.

- 0–3 sec: Immediate visual hook. Start with a striking product moment or a short, bold question. No logo intro.
- 3–9 sec: Establish the user’s problem and why it matters in concrete terms.
- 9–15 sec: Introduce the project and its core idea in one clear sentence.
- 15–38 sec: Show the strongest real product flow. Use actual UI footage, close-ups, animated highlights, cursor movement, and purposeful zooms. Make valuable newly added functionality easy to notice and understand.
- 38–46 sec: Show the value or outcome of that flow, using only outcomes the product can actually demonstrate.
- 46–50 sec: End with the project name and one memorable closing line.

Adapt this structure to the strongest story you find. Keep the video focused and understandable. If it runs long, cut content rather than speeding up narration or exceeding 60 seconds.

## Visual direction

- Build a dark, cinematic look with high contrast, using the project’s own brand colors where possible. If it has no clear visual identity, use deep charcoal or violet backgrounds, crisp white typography, and a vivid accent color.
- Use large, bold kinetic typography for short phrases. Highlight key words, numbers, and interface elements with restrained motion.
- Use quick cuts, punch-ins, match cuts, parallax, and animated callouts to create energy. Give important UI moments enough screen time to be read.
- Alternate between interface close-ups and wider shots that give the viewer context.
- Use subtle lighting, grain, or depth only if they improve the footage. Keep the interface legible.
- Avoid generic stock footage, floating dashboards unrelated to the product, excessive particles, and random transitions.
- Keep captions and important UI within safe margins for projection.

## Audio and narration

- Write concise voice-over that sounds natural when spoken aloud and fits the finished runtime.
- Let the visuals carry the story; do not narrate every click or repeat all on-screen text.
- Add accurate burned-in subtitles.
- Add restrained sound design to reinforce important transitions and product moments.
- Use background music only if an appropriate licensed or project-provided track is available. Keep it below the voice-over.
- If voice-over generation is unavailable, make the video work with on-screen text and sound design alone.

## Accuracy

- Show the current product and real features, including valuable additions discovered during inspection.
- Do not invent capabilities, metrics, user quotes, customer outcomes, or technical claims.
- Distinguish implemented features from planned work. Do not present roadmap features as if they already exist.
- Use cautious wording for uncertain AI outputs.
- Do not claim that data stays local, that the system is private, or that models are fine-tuned unless the code and documentation confirm it.
- If a feature cannot be demonstrated reliably, do not fake it. Choose another real product moment.

## Production and deliverables

- Use the most reliable production method available in the environment, such as real browser recordings combined with motion graphics and code-based editing. Choose tools after inspecting the repository and environment.
- Keep video work in a clearly named, separate directory. Do not make unrelated changes to the product.
- Produce the final 1080p MP4 and the editable project/source files needed to revise it.
- Include the final voice-over script, a timestamped shot list, and a short note explaining which current and newly added features you chose to highlight.
- Render the video, then review the actual output for pacing, readability, subtitle timing, audio balance, and rendering errors. Fix issues before delivering it.
- Verify the final runtime is near 50 seconds and never exceeds 60 seconds.
